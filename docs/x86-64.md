# Separate future x86-64 target

The shipping target remains the tested 32-bit BIOS image. Long mode is planned,
not implemented; it has no verified roadmap credit.

1. Add a distinct boot64 target and image name. Retain the BIOS EDD/A20/E820
   path, check CPUID long-mode support, and reject unsupported CPUs clearly.
2. Build PML4/PDPT/PD/PT structures with 64-bit entries, reserve their frames,
   identity-map the transition code/stack/hardware, validate them before use,
   enable CR4.PAE, load CR3, set EFER.LME, then enable CR0.PG.
3. Install a GDT with a 64-bit code descriptor and far-jump to a separate
   bits-64 kernel entry. Initialize RSP and segment state explicitly.
4. Provide 16-byte IDT gates, 64-bit TSS/RSP0 and IST fault stacks, 64-bit
   interrupt/error frames, and a documented register/stack calling convention.
   Redesign syscall entry, user return and saved contexts for 64-bit addresses.
5. Port allocators, ELF64 bounds and ABI, user page tables and protection tests
   independently. Preserve the existing i386 build/test CI job throughout.

Acceptance needs actual QEMU long-mode register evidence, kernel/user boot and
fault tests, bounded memory allocation, and its own reproducible image. Renaming
the present 32-bit kernel or setting a README checkbox is insufficient.
